## Descripción del proyecto

Aplicación móvil de turnos para el servicio de salud universitario.  
Se aplica un **enfoque iterativo** para refinar la solución mediante aprendizaje y retroalimentación de usuarios en 4 iteraciones de 2 semanas cada una.

## Estructura del repositorio

- `docs/` — Documentación de gestión (enfoque, planificación, estimaciones, riesgos, calidad, métricas)
- `src/` — Código fuente del prototipo
- `tests/` — Pruebas automatizadas
- `.github/workflows/` — Pipeline de integración continua

## Iteraciones

| Iteración | Objetivo | Producto |
|---|---|---|
| I1 | Validar flujo básico de reserva | Prototipo navegable |
| I2 | Validar reprogramación y cancelación | Prototipo con esas funciones |
| I3 | Validar panel admin y privacidad | Prototipo con vista admin |
| I4 | Validar integración simulada y rendimiento | Versión candidata |

## Cómo contribuir

- Cada integrante trabaja en ramas `feat/nombre-tarea` o `docs/nombre-artefacto`.
- Los commits siguen el modo imperativo: `Agrega plan de iteración 1`[reference:2].
- Todo cambio relevante se registra en `docs/decisiones.md`.
