# Unidad 2 — Selección y justificación del enfoque iterativo

## Contexto

El caso requiere iteraciones (no solo incrementos funcionales) porque no se conoce con certeza cómo debe ser el flujo de interacción para estudiantes, profesionales y personal administrativo.

## Ciclo de trabajo

Analizar → Diseñar → Construir → Evaluar → Decidir

## Criterios de decisión por iteración

- **Continuar:** hipótesis validada con evidencia.
- **Reformular:** señal parcial, se ajusta flujo o hipótesis.
- **Descartar:** la evidencia indica pivotar.

## Objetivos de aprendizaje

| Iteración | Objetivo | Producto | Criterio de decisión |
|---|---|---|---|
| I1 | Validar flujo de reserva | Prototipo navegable | ≥4/5 usuarios completa sin ayuda |
| I2 | Validar reprogramación | Prototipo con reprogramación | ≥4/5 reprograma sin asistencia |
| I3 | Validar panel admin y privacidad | Prototipo con vista admin | Admin completa tareas, sin hallazgos críticos |
| I4 | Validar integración y rendimiento | Versión candidata | Cumple umbrales de tiempo, errores y seguridad |
